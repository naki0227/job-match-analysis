# ADR-050: ATS以外の求人ページも取得・解析できるようにする（robotsの4xx、JSON-LDのない求人）

> 状態: 決定（2026年10月08日）。ADR-026の「robots 403で保留」を変更する。ADR-034、ADR-047、ADR-048を前提にする。

## 背景・課題

Money Forward（hrmos）の求人は解析できるのに、LINEヤフーとアクセンチュアの求人は解析できなかった。実際のページで確認した原因は次のとおり。

1. **LINEヤフー: robots.txtが403**
   - robots.txtは、User-Agentに関係なく全員に403を返す。求人ページ自体は200で公開されている。
   - ADR-026は403を「保留」としていたため、すべての求人が取得されなかった。
   - RFC 9309（2.3.1.3）は、4xxのrobots.txtを「unavailable（ルールなし）」と定めている。Googleも同じ扱い。
2. **LINEヤフー: JobPosting JSON-LDもランドマークもない**
   - ページは`Article`としてマークアップされ、`<main>`もない。そのため本文が0文字になった。
   - URLを貼った解析では、求人の同一性（職種名と雇用主）をJobPosting JSON-LDからしか取れず、解析は恒久的に失敗した。
3. **アクセンチュア: `hiringOrganization`が文字列**
   - JSON-LDに`"hiringOrganization": "Accenture"`と書かれている。schema.orgでは許される書き方。
   - 解析側の読み取りはobject形式だけを受け付けていたため、JobPostingごと捨てていた。探索側はすでに文字列を受け付けていた。
4. **DDGSの「結果なし」が、実際はbot判定だった**
   - DuckDuckGoは、1回目の検索の後、bot判定のページ（HTTP 202 "anomaly"）を返す。
   - DDGSはこれを"No results found"として報告する。それを0件として扱っていたため、探索は「求人なし」で完了し、その結果をcacheしていた。

## 決定

1. **robots**: robots.txtが4xx（429を除く）なら、ルールなしとして取得する。429・5xx・通信失敗・別originへのredirectは、これまでどおり保留する。
2. **本文の範囲**: `data-job`・JobPosting・`<main>`のどれもなければ、`role="main"`、次に`<body>`を使う。nav・footer・script・非表示の要素は今までどおり除く。
3. **関連求人の除外**: 「関連ポジション」「その他のポジション」などの見出しも、関連求人と同じく求人本文の終わりとして扱う。
4. **JSON-LDのないページの同一性**（`page-job-identity.ts`）。次の条件をすべて満たす時だけ、ページ自身の記載から同一性を作る。
   - h1がちょうど1つで、それが一覧ページの見出し（「採用情報」「Careers」など）ではない。
   - 雇用主は`og:site_name`、なければJSON-LDのOrganization名（1つだけの場合）。
   - `<title>`または`og:title`に、職種名と雇用主の両方が含まれる。
   - 本文に求人の要素（業務内容・応募資格・勤務地・給与・雇用形態・勤務時間）が2つ以上ある。
   
   JobPosting JSON-LDがある場合は、常にそちらを優先する。
5. **JSON-LD**: `hiringOrganization`が文字列でも受け付ける。
6. **DDGS**: "No results found"は`unavailable`（再試行できる失敗）として報告する。本当に結果がない検索も、再試行の後に失敗するだけで、誤った「求人なし」は保存されない。

## 結果（実ページ）

| ページ | 変更前 | 変更後 |
|---|---|---|
| LINEヤフー 求人2件 | robotsで保留 | 取得・同一性あり。年収1000万〜1450万、810万〜1500万を読める |
| アクセンチュア 求人 | 同一性がなく恒久的に失敗 | 取得・同一性あり。勤務地5件、雇用形態を読める |
| Money Forward | 成功 | 変わらず成功 |

## 残課題（この決定では扱わない）

- **探索（企業名からの検索）の質**:
  - LINEヤフーでは、採用トップや職種一覧を求人として受け入れてしまう。リンクの取得上限（20ページ）をナビゲーションのリンクで使い切り、求人の詳細ページまで届かない。
  - アクセンチュアの求人へのリンクはJSで描画されるため、静的なHTMLにはない（求人のsitemapは公開されている）。
- **DDGSの信頼性**: DuckDuckGoのbot判定が頻繁に出るため、本番の探索はほとんど結果を出せない可能性が高い。

## 見直し条件

- 4xxのrobots.txtを根拠に取得したサイトから、拒否や利用条件の連絡があった場合は、そのサイトを`siteAllowed`で遮断する。
- ページの同一性を誤る例が出た場合は、条件を厳しくする。
