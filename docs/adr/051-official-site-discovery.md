# ADR-051: 企業名からの求人探索を、検索エンジンに頼らず公式サイトから行う（無料）

> 状態: 決定（2026年10月08日）。ADR-047（DDGSによる探索）の主な経路を置き換える。ADR-034・ADR-050を前提にする。

## 背景・課題

ADR-047の探索は、DDGS（DuckDuckGo）の検索結果を手がかりにしていた。2026年10月の調査で、次の問題がわかった。

- DuckDuckGoは、1回目の検索の後にbot判定（HTTP 202 "anomaly"）を返す。そのうち、この環境のすべての検索を拒否するようになった。本番（Azure）の探索は、ほとんど結果を返せていない可能性が高い。
- 結果が返っても、採用トップや職種の一覧ページを求人として受け入れていた。またリンクをたどる上限を、ナビゲーションのリンクで使い切っていた。

有料の検索API（Brave、Claude APIなど）は使わず、無料で進めたい。

## 決定

**企業名 → 公式サイト → 公式サイト自身が公開する求人の場所**、の順で探す。検索エンジンは補助にする。

1. **公式サイトの特定**（`official-site.ts`）: 日本語Wikipediaの企業名の記事 → Wikidataの項目 → 「公式ウェブサイト」（P856）。
   - 取得するのは、robots.txtが許可するページだけ。Wikipediaの`/wiki/`の記事と、Wikidataの`Special:EntityData`。検索API（`/w/api.php`）とSPARQLは、robots.txtで禁止されているため使わない。
   - 記事名は「〇〇」「株式会社〇〇」「〇〇 (企業)」を順に試す。推測による検索はしない。
   - 曖昧さ回避のページや、企業ではない項目（P31が企業の種類でも、業種P452でもない）は除く。項目の名前が企業名と一致しない場合も除く。
2. **手がかりの収集**（`official-leads.ts`・`career-links.ts`）:
   - 公式トップページから、採用ページとATS（hrmos・talentioなど）へのリンクを集める。
   - 公式サイトと採用サイトのsitemap（robots.txtの`Sitemap:`、なければ`/sitemap.xml`）から、**同じ形のURLが8件以上並ぶ採用配下のURL**を求人の詳細ページとして集める（例: `/job-categories/ly00372/`、`/jobdetails?id=R…_ja`）。その親を一覧ページとする。
   - 日本語の企業名なら、日本語のページを優先する。新卒・インターンを求めていない時は、学生向けのページを後回しにする（求めている時はその逆）。
   - 最後に、`careers.`・`recruit.`・`jobs.`のサブドメインも候補にする。
   - sitemapとrobots.txtの取得は、1回の探索で最大6件（`CRAWLER_DISCOVERY_MAX_SITEMAP_FETCHES`）。詳細ページの候補は最大15件（`CRAWLER_DISCOVERY_MAX_SITEMAP_DETAILS`）。
3. **探索**（`discover-jobs.ts`）:
   - 公式サイトの手がかりを先に処理する。それで求人が見つからない時だけ、検索エンジンに問い合わせる。検索エンジンが設定されている時は、公式の手がかりが使えるのは取得上限の3/4までとし、残りを検索のために取っておく。
   - JSON-LDのない採用ページが、同じ形の求人ページへのリンクを3件以上持っていれば、一覧ページとしてたどる。ただし、そのページ自身もその形の一つなら、関連求人を載せた求人ページとして受け入れる。
   - リンクは最大3段までたどる（採用サイト → カテゴリ → 一覧 → 求人）。求人らしい兄弟リンクとATSのページは、待ち行列の先頭に入れる。
   - 求人の会社名が別名でも受け入れる（例: アクセンチュアの「Accenture」）。Wikidataの名前・別名と一致すれば、利用者が検索した名前で保存する。
   - 公式サイトのドメイン上の求人は、`official`として扱う。
4. **設定**: `CRAWLER_WEB_SEARCH_PROVIDER=ddgs`は「公式サイト＋DDGS」。`official`は「公式サイトのみ（検索しない）」。既存の環境変数のままで動く（新しい上限には既定値がある）。

## メリット

- 無料で、検索エンジンのbot判定に左右されない。
- 公式サイトが自分で公開している求人だけを手がかりにする。

## デメリット

- Wikipediaに記事のない企業や、記事名が企業名と異なる企業は見つからない（検索エンジンにフォールバックする）。
- 求人一覧をJSでしか描画せず、sitemapもないサイト（メルカリなど）は見つからない。
- sitemapからは職種名がわからないため、職種を指定した検索でも、候補はsitemapの順になる。

## 見直し条件

- 公式サイトから見つからない企業が多い場合は、gBizINFO（無料のAPIトークンで、法人番号と企業URLを引ける）を参照データに加える。
- JSでしか描画しない採用サイトが多い場合は、一覧ページのブラウザ描画の条件を見直す。
