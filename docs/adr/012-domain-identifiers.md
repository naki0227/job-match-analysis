# ADR-012: CareerProfileの軸IDと勤務地コード

## 背景と課題

Issue #12の不変なCareerProfileには、8軸全体の版混在を検出できる安定した軸IDと、勤務地条件を検証できる地域IDが必要になる。

## 選択肢

- 軸を固定キーと共通カタログ版で管理し、勤務地を都道府県コードで保持する。
- 任意の軸IDと自由記述の地域を受け入れる。追加は容易だが、誤字や表記揺れをドメイン境界で拒否しにくい。
- 軸だけ固定し、地域はより細かい市区町村単位にする。詳細な勤務地希望を表せるが、MVPの入力と正規化が複雑になる。

## 採用した案と理由

ユーザーの判断により固定の8軸IDと都道府県コードを採用する。軸の版は8軸全体で共有する。都道府県コードは[総務省統計局の一覧](https://www.stat.go.jp/data/mesh/m_itiran.htm)の2桁 `01`〜`47` とする。IDと軸名の対応は[評価軸の仕様](../assessment-axes.md)に記す。

## メリット

- 未知の軸ID、重複、軸版の混在を拒否できる。
- 都道府県の表記揺れをプロフィール内に持ち込まない。
- 版を明示して過去のプロフィールを保持できる。

## デメリット

- 1軸だけ変更する場合もカタログ全体の新版が必要になる。
- 市区町村単位や海外の勤務地希望はこの版では表せない。
- 求人の地名からコードへの変換は別の境界で必要になる。

## 見直し条件

軸の追加・意味変更が必要になったときは、新しいカタログ版と移行方針をレビューする。市区町村や海外の勤務地がMVPの対象になった場合は、地域IDの拡張を検討する。既存データを無断で読み替えない。
