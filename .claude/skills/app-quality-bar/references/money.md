# 課金：お金を払いたくなり、安いと感じる質

本人の方針（2026-11-05）：**課金要素は必ず入れる。お金を払いたくなるレベルで、安く感じることができる質を求める。** 課金の形（買い切り・サブスク・追加パック）は AI がアプリごとに選び、App Store Connect の商品と価格も AI が作る（本人の回答 2026-11-05）。

出典の略記：SR = StudyReel、GM = 五十音マインスイーパー。SR の値は `docs/research/market.md`・`docs/pro-value.md`、GM は `docs/endless-economy-plan.md`。

## 1. 原則
- **核は無料で十分に使える**。SR は録画・記録・仲間・顔モザイクを無料のまま、広告も出さない（`market.md:258`）。無料の範囲で、そのアプリの価値が一度は分かること
- **Pro は「なくても困らない見た目」にしない**。SR の反省：これまでの Pro は動画の見た目（ロゴなし・フォント・BGM・テーマ）が中心で、本人には「なくても困らない」ものが多かった（`pro-value.md`）。Pro には、**使い込むほど欲しくなる深さ**を入れる（詳しい振り返り・追加のお題や型のパック・長い期間の記録・書き出し・ウィジェットの種類・保護者や仲間に見せる機能）
- **「安い」と感じさせる**のは値段だけではない。払う直前に、もらえる中身が具体的に見えていること、同じ分野のアプリより中身が多いか同じで値段が安いか同じであること
- **押し付けない**。起動直後や操作の途中に課金の画面を出さない。何度も出さない（Forest への ★1「pop ups after pop ups」「Stop asking for money」、`market.md:119`）
- **お金で残高を持たない**：毎日のアプリはサーバーを持たないので、ジェム・コインなどの消費型は入れない（GM：「No unchecked client-side grants」。残高はサーバーで守る前提）

## 2. 形を選ぶ（AI がアプリごとに決め、理由を README に書く）
| 形 | 選ぶとき | 例 |
|---|---|---|
| 買い切りの Pro（非消耗型） | 価値が「機能の解放」で、あとから中身が増え続けない | 全てのお題・全テーマ・詳しい統計・書き出し |
| 追加パック（非消耗型を複数） | 中身が分かれていて、欲しい人だけ買える | 場面別のフレーズの束、実験の型の束、盤面のセット |
| サブスク（自動更新） | 続けて価値が増える（毎月の新しいお題、週と月の振り返り、保護者への報告） | SR：月 ¥300・年 ¥2,000、1週間のお試し（`market.md:13`） |

- サブスクにするなら、**続けて増える価値**を1行で書く。書けなければ買い切りにする
- 年額を前に出し、月あたりの額を並べて見せる（SR の方針、`market.md:258`。RevenueCat の Education では年額を選ぶ人が多い、`market.md:192`）
- 学生などカードを持たない人が多いなら、**ファミリー共有**を使う（SR は保護者が買えば子も使える、`pro-value.md`。一度オンにすると戻せない）

## 3. 値段の決め方（その日に確かめる）
1. 同じ分野のアプリを 3 つ以上、App Store の公開ページで調べ、課金の形と値段と中身を表にする（出典の URL と日付）。SR の例：Studyplus ¥600・YPT ¥400〜¥800・Forest 月 ¥680、SR は月 ¥300・年 ¥2,000 で「競合と比べて安い方」（`market.md:18-22,189`）
2. 中身が同じか多く、値段が同じか安い位置に置く。目安の出発点：買い切りの Pro は ¥300〜¥600、追加パックは ¥160〜¥300、サブスクは月 ¥300・年 ¥2,000 前後（SR）。出発点のまま決めず、1 の表から理由を書く
3. 値段は StoreKit の `displayPrice` を表示する（GM：「exact displayed price comes from StoreKit」）。コードに金額を書かない
4. 決めた値段・形・理由・比べた表を README の「課金」に残す。本人は提出の前に見て、変えたければ変える

## 4. 課金の画面（ペイウォール）
- **出す場面は、価値を感じた直後**：最初の記録を保存した・最初のクリアをした・無料の上限に届いた、など。起動時に出すよりお試しの開始が倍になる（Adapty：直後 65%・起動時 31%、`market.md:194`）
- 画面の中身：Pro でできることを **3 つ以上、具体的に**（絵か実物の見本つき）、値段（年額を先、月あたりの額）、お試しがあれば期間、**購入を復元**、サブスクなら利用規約とプライバシーポリシーへのリンクと自動更新の説明
- 日本向けには縦に長いスクロールの画面を試す価値がある（`market.md:193`）
- 見た目は StudyReel のトーン（`look.md` §0）。煽る赤や点滅、カウントダウンは使わない
- 閉じる手段をはっきり置く。閉じたあと、同じ日にまた出さない
- Pro の中身を 1 回だけ試せる（お試しの見本・1 枚だけ書き出せる、など）と、価値が伝わる（SR の方針：お試し中に Pro の機能を 1 回使ってもらう、`pro-value.md`）

## 5. 作り（StoreKit 2・サーバーなし）
- `Product.products(for:)` で商品を読み、`purchase()` で買い、`Transaction.updates` を起動時から聞き、`Transaction.currentEntitlements` で今の権利を決める。`VerificationResult` が `.verified` のものだけ使う
- 権利の判定は1か所（`Entitlements` のような型）にまとめ、画面はそれを見るだけ。プロトコルで差し替えられる形にし、テストは偽物で書く（購入済み・未購入・返金・期限切れ）
- `Configuration.storekit` を置き、商品 ID と値段を本番と同じにする（手元とテスト用）
- 商品が読めない（通信なし・審査前）ときの状態も作る：「いまは購入できません」と次の一歩。Pro の画面が空にならない
- 商品 ID は `<Bundle ID>.pro`、`<Bundle ID>.pack.<名前>`、`<Bundle ID>.sub.yearly` / `.monthly` の形

## 6. 審査とお金の決まり
- App 内課金の商品は、初めてはアプリのバージョンと一緒に審査に出す。審査用のスクリーンショット（課金の画面）と説明が要る
- 有料のアプリの契約（Paid Apps Agreement）が有効でないと売れない（本人が確認する）
- 審査への提出は本人が行う（daily のテンプレートの決まり）

## 7. 確かめる
- テスト：権利の判定（買った・買っていない・返金・期限切れ・復元）を偽物で確かめる
- TestFlight：サンドボックスで実際に買い、Pro が開くこと、アプリを入れ直して復元できることを確かめ、結果を報告に書く（確かめていないなら「未確認」と書く）
- 自分に問う：「この値段で、この中身なら、自分は払うか。安いと感じるか」。理由を 3 つ書けなければ、中身を足すか値段を下げる
