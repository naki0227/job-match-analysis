# ADR-011: 重要度0と必須条件の扱い

## 背景と課題

Issue #11で `importance=0`、最低年収、勤務地、フルリモート必須の意味を決める必要がある。公開求人の記載には欠落や範囲があり、根拠がない条件を一致・不一致へ強制すると利用者を誤解させる。

## 選択肢

- 重要度0を比較対象から外し、希望値は保存する。別案は未回答として扱うこと。
- 年収は日本円の額面年収として掲載範囲で比較する。別案は異なる通貨・期間を換算して比較すること。
- 勤務地・フルリモートは個別求人の明示情報で判定する。別案は会社全体の制度から個別求人へ推定すること。

## 採用した案と理由

ユーザーが上記の先頭の案を承認した。未回答と重要度0を区別し、根拠のある条件だけを判定する。金額範囲が基準をまたぐ場合や求人固有の条件が不明な場合は `unknown` を返す。詳細な例は[評価軸の仕様](../assessment-axes.md)に記す。

## メリット

- 希望を保存したまま、評価に使わない軸を明示できる。
- 換算や会社制度からの推測による誤判定を避けられる。
- 必須条件の情報不足を利用者へ示せる。

## デメリット

- 月給表示・外貨表示・幅のある年収の求人では `unknown` が増える。
- 会社の制度が公開されていても、個別求人の条件がなければ判断できない。

## 見直し条件

異なる通貨・期間の給与を扱う必要が生じた場合、換算元・時点・丸め方を別途設計する。勤務地の地域単位やAPI表現は対応Issueで確定する。実際の求人で `unknown` が多い場合は根拠を調査してルールを再検討する。
