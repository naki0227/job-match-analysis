## 2. 既定は StudyReel の静かな動き（道具・学習・記録・日記のアプリ）
- 落ち着いたフェードが中心：easeOut 0.25（カードの切り替え）、0.35（オンボーディングを閉じる）、0.5（スプラッシュ。1.2 秒待って消す）
- 案内の穴が次の場所へ移る：`.spring(response: 0.45, dampingFraction: 0.85)`（`CoachMarks.swift:105`）。弾ませすぎない
- 吹き出しは `.opacity.combined(with: .scale(0.96))`（:163）。大きく伸び縮みさせない
- 完了・記録・共有の瞬間だけ、少しだけ印象を強くする（数字の `contentTransition(.numericText())`、テープが貼られる、ポラロイドが少し傾いて置かれる、など）。紙吹雪・火花・画面の揺れは使わない
- 振動は控えめに：選ぶ＝`.selection`、完了＝`.success`。連打で鳴らさない

## 4. 動きの決まり
- 主役の操作には、**位置・大きさ・回転のどれか**が小さく変わる動きを入れる（フェードだけで済ませない。ただし大きく弾ませない）
- ゲームの部分では、失敗は「揺れ」、成功は「弾む・広がる」、連続は「時間差」で表す（GM の型）
- 紙吹雪や火花は、**固定の乱数**で毎回同じに（スクリーンショットとテストが安定する）
- SwiftUI では `spring(response:dampingFraction:)`・`keyframeAnimator`・`phaseAnimator`・`contentTransition(.numericText())`・`symbolEffect` を使い分ける
- **動きを減らす設定**（`@Environment(\.accessibilityReduceMotion)`）がオンなら、めくり・揺れ・紙吹雪・弾みを止め、値を直接変える。チュートリアルは止まった絵にする（GM `motion.ts:8-29`）。SR は未対応（弱い所）なので真似しない

## 5. 振動
- 2本とも弱い：GM は 0 件、SR は成功の通知 3 か所だけ（休憩の開始・終了、バーコード読み取り）。**新しいアプリでは上乗せする**
- SwiftUI の `.sensoryFeedback` を手応えの表の行ごとに付ける：押す・選ぶ＝`.selection`、1つ成功＝`.impact(weight: .light)`、完了＝`.success`、失敗＝`.error`、大きな当たり＝`.impact(weight: .heavy)`
- 連続して鳴りすぎない（連鎖は最初と最後だけ、など）

## 6. 音（ゲーム・遊びの要素があるとき）
- 効果音の音量を段階で決める：GM は tap 0.4・open / chain / start 0.6・over 0.7・mine / correct 0.8・BGM 0.3（`sound/sounds.ts:19-31`）
- **鳴らす音の優先順位を1か所で決める**：正解 > 地雷 > 終了 > 連鎖 > 1 マス > 不正解。問題が変わった瞬間は鳴らさない（`sound/transitions.ts:16-32`）
- 大きな音のあとは間を空ける：爆発音が消えるのを待って 700ms 後に終了の音（`Stinger.tsx:57-62`）
- 消音スイッチに従い、ほかのアプリの音と混ぜる（`playsInSilentMode: false`・`mixWithOthers`）。効果音と BGM を別々にオフにできる設定を持つ
- 道具のアプリ（SR）は、効果音より **作業中の環境音・BGM**（雨・ホワイトノイズ・ピアノなど 7 本）が価値になる
