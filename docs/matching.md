# MVP MatchEngineの判定規則

Issue #13の純粋ドメイン計算。本人の確定済みCareerProfile版と、公開情報に根拠のある評価版を比較する。採用適性や総合的な適合率は返さない。

## 入力と版

- 本人の希望は8軸の `preference: 0..100`、`importance: 0..100`。公開評価側の軸値は、[軸のルーブリック](assessment-axes.md)に沿って0・50・100のいずれかに評価できたものだけを受け取る。
- Jev Scoreはそのまま公開評価側の軸値として使わない。公開資料からアンカーへ評価する方法と版は別途定義する。根拠がない場合は `unknown`。
- CareerProfileと評価側の8軸カタログ版が異なる場合、その対象の軸比較は `incompatible` とする。求人と会社は独立に比較可能性を判定する。

## 軸ごとの結果

| 条件 | 結果 |
|---|---|
| `importance=0` | `excluded`。希望値は残し、軸比較から除く |
| 根拠付きの値があり、希望値との差の絶対値が25以内 | `close`（近い） |
| 根拠付きの値があり、差が25を超える | `different`（相違） |
| 根拠なし・矛盾・古い資料 | それぞれ `unknown` / `conflicting` / `stale`。現在の一致・相違は付けない |
| 対象評価に軸がない | `unknown` |

重要度が1以上の場合も総合点へ重み付けしない。重要度は結果に保持し、表示順や強調への利用を後続UIで決める。軸の数値差は表示可能だが「適合率％」と呼ばない。

| 希望値 | 評価アンカー | 差 | 結果 |
|---|---|---|---|
| 75 | 50 | 25 | `close` |
| 76 | 50 | 26 | `different` |
| 0 | 0 | 0 | `close`（重要度が0なら `excluded`） |

## 会社と求人

求人の軸結果を本人向けの主結果とする。会社の軸結果は別の参考情報として返し、求人の根拠がない軸へ値を補わない。会社全体の制度や文化が、その求人に当てはまると推測しない。会社側だけ版が異なる場合も、求人側の比較を妨げない。

## Hard Constraint

最低年収・勤務地・フルリモート必須は[確定済みの条件](assessment-axes.md#重要度と必須条件)で個別に確認し、`met / unmet / unknown / not_required` を返す。`unmet` には機械的に識別できる衝突理由を付ける。給与の単位違い、範囲が基準をまたぐ場合、情報不足・矛盾・古い情報は `unknown`。軸の `close` があっても `unmet` を相殺しない。総合％は出さない。
