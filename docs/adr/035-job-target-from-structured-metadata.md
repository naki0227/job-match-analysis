# ADR-035: 公開求人の評価対象を明示メタデータから作る

## 背景・課題

解析受付はURLだけを保存するが、評価の確定には`evaluation_targets`が必要。URLのホスト名や見出しから会社名を推測すると、求人と会社の対応を誤る。会社名はDBで一意ではない。

## 選択肢

1. URLのホスト名と見出しから会社・求人を推測する。対象ページは増えるが、求人媒体のドメインを雇用主と誤認する。
2. 単一の`JobPosting` JSON-LDに求人名と`hiringOrganization.name`がある場合だけ新しい対象を作る。対象ページは限られるが、根拠のない同定を避けられる。
3. ユーザーに会社名・求人名を入力させる。多くのページで動くが、共有評価に本人の入力を混ぜる契約変更が必要。

## 決定と理由

最初の実装は2を採用する。複数の異なる`JobPosting`がある一覧ページ、名前が欠けた文書、見出しだけのページは対象を作らない。URLごとにジョブの有効leaseを確認し、service role専用RPCで既存の同一求人名・雇用主名を再利用する。名前が変われば別の対象を作る。別URLの会社名一致だけでは企業を統合しない。対象作成と評価確定はそれぞれ短いDBトランザクションとし、外部取得・Jev呼出し中はトランザクションを保持しない。

## メリット・デメリット・見直し条件

同一URLの再解析で評価対象を安定して使い、無関係な企業の評価を混ぜない。JSON-LDのないページは解析できず、評価失敗時に対象行だけ残る場合がある。実サイトで未対応ページが多ければ、会社・求人の同定方式とユーザー入力の契約を再検討する。JSON-LDも公開ページ側の自己申告なので、企業の真正性を保証するものではない。
