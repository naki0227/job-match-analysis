# iOS アプリの品質基準（StudyReel・五十音マインスイーパーの水準）

本人の評価（2026-11-04）：毎日のアプリは「淡白」「内容がうすすぎる」。StudyReel や五十音マインスイーパーのように **UI に凝り、中身を厚く** する。
ここの値はどれも、その2つのアプリのコードで測ったもの（出典は `references/` に file:line で書いてある）。一般論で埋めない。

## トーンの既定は StudyReel（オシャレ・透明感・清潔）
本人の希望（2026-11-05）：「マインスイーパー側に寄せてるけど StudyReel 側に寄せて欲しかった。オシャレな感じ」。
- **見た目の既定は StudyReel**：淡い色（明度 0.74〜0.85）、白に近い地、セリフの見出しと数字、細い線、弱い影、静かなフェード、ほんの少しの紙の飾り（テープ・方眼・ポラロイド）。本人の好み：透明感・韓国風・Vlog 風の清潔さ・画面をごちゃごちゃさせない（Vault の `06-Personal/collaboration-and-communication.md`）
- 五十音マインスイーパーから取るのは、**ゲームや遊びの部分の手応え**（めくり・連鎖・揺れ）と、中身の量・状態の作り方だけ。濃い色・太さ 800〜900・判子調の太い枠・紙吹雪・火花を、道具・学習・記録のアプリの見た目に持ち込まない
- 詳しくは `references/look.md` §0（トーンの数値）

## まず避けること（淡白になった原因）
2026-11-03・04 の2本（言いたい英語ドリル、じぶん実験室）は、**同じ骨組みに色だけ変えた**見た目だった：白いカード（padding 18・角丸 22・影 opacity 0.06 / radius 12 / y 4）＋2色の斜めグラデーションのボタン＋上だけ淡い背景グラデーション＋ SF Symbols。

- この組み合わせを、新しいアプリの既定にしない。**前に作ったアプリの Theme・部品をコピーしない**（見た目の焼き直しは審査 4.3 の危険でもある）
- 「カードを並べる」「グラデーションのボタン」「SF Symbols だけのアイコン」で個性を出そうとしない
- 2026-11-05 の作り直しでは、反対に**濃くて強い**見た目になった：赤シート `#E0283A`（明度 0.52）、朱のハンコ `#E0533D`（0.56）、黄 `#F2C63A`（0.59）、分類ごとに違う色。世界観（単語カード・実験ノート）は良いが、色と飾りが強すぎてオシャレにならない

## 必ず満たすこと（足りないものがあれば完成にしない）
1. **題材の世界観を部品にする**（`references/look.md` §1）：題材の現物（紙・道具・場所・札・盤）から形を1つ以上選び、自作の Shape / Canvas / 部品として描く。StudyReel の方眼とテープ、五十音の盤面がこれに当たる
2. **色・書体・形を1か所で決める**（`look.md` §2〜4）：1色ごとに5段階（accent / soft / deep / paper / 飾り）、2書体の使い分け、角丸と余白の段階、影は2〜3種類まで
3. **主な操作ごとに手応えを設計する**（`references/feel.md`）：押す・成功・失敗・連続・完了の5つそれぞれに、動き＋振動（＋必要なら音）を決め、表にして残す。動きを減らす設定で全部止まる
4. **毎日開く理由を2つ以上と、続ける仕組み**（`references/depth.md` §1）：今日のお題・通知・連続記録・積み上げの見える化・共有カード・ウィジェットなどから
5. **画面ごとに状態を全部作る**（`depth.md` §2）：空・読み込み・失敗・許可なし・初回。空の画面は「何をすれば価値が出るか」の一文と、次の一歩のボタン
6. **最初の 10 秒**（`depth.md` §3）：起動 → 3ページ以内のオンボーディング → 見本のデータか、最初の1回をその場で体験させる
7. **中身の量**（`depth.md` §4）：手で用意したデータ（問題・お題・文例・型）を、1日で遊びきれない量で入れる。アプリの価値が「入力欄と結果の表示」だけにならない
8. **トーンを StudyReel に合わせる**（`look.md` §0）：主な色の明度 0.72 以上、アプリの色は1系統、太字は少なく、飾りはほんの少し
9. **撮って採点して、基準に届くまで直す**（`references/review.md`）：9つの観点を 0〜3 で採点し、合計 20 以上、0 が1つもない、トーンは 2 以上、まで直す

## 進め方
1. 題材の棚卸し：題材に出てくる物・場所・道具・紙もの・数字・決まった手順を 10 個書き出す（`look.md` §1）
2. 世界観を決める：「このアプリでは〔棚卸しの1つ〕が〔部品〕になる」と1文で書く。似た既存アプリの名前を入れても成り立つなら考え直す
3. トークンを決めて `Theme.swift` に書く（色の段階・書体・角丸・余白・影）。色は `look.md` §0 の明度の範囲で選び、数値で確かめる
4. 手応えの表（`feel.md` の形）を書いてから実装する
5. 中身（データ・仕組み・状態）を `depth.md` の最低線まで作る
6. 全画面とダークモードを撮り、`review.md` で採点 → 低い観点から直す → 撮り直す

決めた世界観・トークン・手応えの表・採点の結果は、そのアプリのリポジトリ（README か docs）に残す。
