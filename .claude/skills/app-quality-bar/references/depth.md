# 中身の深さ：毎日開く理由・状態・最初の10秒・量

出典の略記：SR = StudyReel、GM = 五十音マインスイーパー。

## 1. 毎日開く理由と続ける仕組み（2つ以上）
| 仕組み | 実例 | 出典 |
|---|---|---|
| 今日のお題 | GM：今日の一問。毎朝 7:05 に通知 | `daily/reminder.native.ts:34-58` |
| 連続記録 | GM：ギブアップや日を飛ばすと途切れる | `daily/streak.ts:3-22` |
| 途切れても責めない言い方 | SR：「連続記録が途切れました」より「おかえり! 今年は合計○日」 | `docs/research/science.md:170` |
| 積み上げの見える化 | SR：1年のヒートマップ（Canvas、マス 9pt・間隔 2・濃さ 5 段階。濃さは最大値ではなく時間の区切りで決める）、Swift Charts の棒グラフ（高さ 150、Y 軸なし）、点数の折れ線 | `StudyHeatmapView.swift:3-36`、`StudyStatsView.swift:140-159`、`docs/research/ios.md:189-199` |
| 共有カード | SR：`ImageRenderer` で 360×640 を scale 3 → 1080×1920。GM：答えが見えない色だけの盤面（🟦🟧）を共有 | `GoalShareView.swift:177-178`、`DailyShareCard.tsx:1-3` |
| ウィジェット | SR：ホーム（small / medium、セリフの数字 30/38pt）、Live Activity（Dynamic Island 全形）、コントロールセンター（25 分を開始）。GM：大きいウィジェットでマスを直接タップでき、続きをアプリで遊べる。ロック画面用も | `StudyReelWidget/`、`targets/widget/` |
| ショートカット | SR：AppShortcuts | `StartStudyIntent.swift:59` |
| 小さな驚き | GM：抽選のプレゼント、季節の配色 | `daily/gift.ts`、`theme/season.ts` |

最低線：**今日の何か（お題・目標・記録）＋積み上げの見える化**の2つ。ウィジェットか共有カードを、作れる範囲で1つ足す。

## 2. 画面ごとの状態
画面ごとに次を作り、撮って確かめる。

| 状態 | 実例 |
|---|---|
| 空 | SR ホーム：「勉強した時間が、ひとつのVlogになる。」＋最初の記録を作るボタン（`StartView.swift:497-516`）。統計・教材・Vlog・共有・仲間でも、それぞれの一文（6 画面） |
| 読み込み | SR：Paywall・設定・仲間・Vlog の進捗バー。GM：今日の一問の「読み込み中…」 |
| 失敗 | SR：「プランを読み込めませんでした」、iCloud がない／制限／失敗の3種。GM：「通信できませんでした／電波のよいところで開き直してね。」、オンラインのエラー文 23 種と英訳、知らないエラーは共通文 |
| 許可なし | SR：カメラ・写真が拒否されたら「設定を開く」付きの案内（`StartView.swift:241-249`） |
| 代わりがある | GM：今日の問題が未公開なら前日の問題に切り替える（`DailyScreen.tsx:133-147`）。条件に合う問題が 0 件ならモードを無効にする |
| 中断からの復帰 | SR：離れていた間に止まったときの再開カード、強制終了からの復元、空き容量が少ない警告 |

文は利用者の言葉で、次に何をすればよいかを書く（「エラーが発生しました」だけにしない）。

## 3. 最初の 10 秒
- 起動 → オンボーディング **3〜4 ページ**（SR：撮る／整える／残る。GM：横スワイプ 4 ページ）。最後のページで不安を消す一文（SR：「カメラの映像は端末の中だけで使い、外に送りません」、`OnboardingView.swift:81-97`）
- 初めて触る画面には案内（SR の CoachMark：暗幕 黒 0.68、対象を `.destinationOut` でくり抜き、穴は対象より左右 10・上下 8 広く角丸 14、白 0.9・太さ 1.5 の縁。説明は対象が上 55% にあれば下に出す。`CoachMarks.swift:78-115`）
- チュートリアルは文章より **動く見本**（GM `tutorial/scenes.tsx`）
- 空の画面で終わらせない：見本のデータか、その場で最初の1回を体験させる
- 「使い方をもう一度見る」を設定に置く（SR）

## 4. 中身の量
- **手で用意したデータを、1日で遊びきれない量で入れる**：GM は問題 約 22,000 件（日本語 約 14,400・英語 約 7,600）、詰め五十音 30 問、学習用の単語 164 語。同じ条件の別解も正解にする
- 道具のアプリも、選べる型・素材を持つ：SR はテーマ色 8 色（各 5 段階）、動画の文字のフォント 7 種、フィルター 5 種、環境音 7 本
- **遊び方・使い方の幅**：GM はモード 7 つ（今日の一問・エンドレス・ボット 3 段階・詰め・出題して遊ぶ・学習・オンライン）。新しいアプリでも、主な流れ1つ＋変化（難しさ・モード・お題の種類）を最低 2 つ
- 設定：SR は 9 区分・約 20 行（テーマ色・撮影・モザイク・保存先・学習・バックアップ・Pro・共有・その他）。最低でも、音・振動・通知・見た目（色）・使い方をもう一度・プライバシーの説明
- データの持ち方：SR は SwiftData のモデル 6 つ。記録が積み上がるアプリは、あとから増える項目（目標・タグ・メモ）も最初から持つ

## 5. 多言語とアクセシビリティ
- 言語：SR は 5 言語（ja・en・ko・zh-Hans・zh-Hant）、ウィジェットと InfoPlist・AppShortcuts も訳す。GM は ja・en。最低でも ja・en
- 読み上げ：要素を「中身＋状態」で1つにまとめる（GM「地雷 答えに2回登場」、`boardLabels.ts`）。マスの集まりは1文にまとめて読ませる（SR ヒートマップ、`StudyHeatmapView.swift:24`）。飾り（テープ・絵文字）は読み上げから外す
- 押せる物は 44pt 以上、動きを減らす設定に対応、Dynamic Type に追従（SR は未対応なので上乗せ）

## 6. お金と広告（課金の基準は `money.md`。ここは2本の実例）
- GM：広告は 1 画面に 1 枚、設定と結果の画面だけ。対局中は操作部から 150pt 離し、1 局の途中で広告の位置を動かさない（`ads/types.ts:1-3`、`PinnedBannerScreen.tsx:14-38`）
- SR：広告は出さず核の機能は無料。課金の画面は最初の動画を保存した直後に出し、年額を前に出す（`docs/research/market.md:258`）。反省：見た目だけの Pro は「なくても困らない」（`docs/pro-value.md:38`）
