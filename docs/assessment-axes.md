# MVPの就業価値観8軸

Issue #11で採用した、本人の希望と公開情報を比較するための軸。これは自己申告による意思決定支援であり、人格や採用適性の診断ではない。

各軸には `preference: 0..100` と `importance: 0..100` を別々に持つ。下の0/50/100は尺度の意味を示すアンカーであり、軸の中間値の計算方法やMatchEngineの重み付けはここでは定めない。本人への質問と公開資料の評価基準は同じ軸を使うが、入力源を混同しない。`importance=0` でも希望値は保存し、その軸をマッチ判定から除外する。

| 軸 | 本人への質問 | 本人の希望 0 / 50 / 100 | 公開資料で確認する 0 / 50 / 100 |
|---|---|---|---|
| 働く場所 | どの程度、在宅で働きたいですか？ | 原則出社 / 出社と在宅を併用 / フルリモート | 出社前提の明記 / 出社と在宅を併用する条件の明記 / フルリモート可の明記 |
| 裁量 | 仕事の進め方をどの程度自分で決めたいですか？ | 手順が明確 / 一部を自分で決める / 方針や進め方を自分で決める | 手順・承認経路の明記 / 一部の裁量範囲の明記 / 方針や進め方の決定権の明記 |
| 協働 | 日々の仕事をどの程度チームで進めたいですか？ | 個人中心 / 個人作業と共同作業を併用 / チーム中心 | 個人担当の明記 / 個人と共同の両方の明記 / チームでの共同責任の明記 |
| 成長の方向 | 今の専門性を深めることと、新しい領域に挑むことのどちらを重視しますか？ | 今の専門性を深める / 両方 / 新しい領域に挑む | 特定分野を深める職務の明記 / 両方の明記 / 新しい領域を担う職務の明記 |
| 仕事の変化 | 仕事の進め方や優先順位はどの程度変化してほしいですか？ | 予測可能な仕事 / 適度な変化 / 変化が速い仕事 | 定型・安定した職務の明記 / 定型と変化の両方の明記 / 頻繁に優先順位が変わる職務の明記 |
| 勤務時間の柔軟性 | 働く時間をどの程度自分で調整したいですか？ | 固定時間 / 一部を調整できる / 広く調整できる | 固定勤務時間の明記 / 時差勤務や一部フレックスの明記 / コアタイムなし等の広い時間裁量の明記 |
| 役割の幅 | 一つの専門領域と幅広い業務のどちらを希望しますか？ | 特定領域に集中 / 複数領域を一部兼務 / 幅広い領域を担当 | 担当領域が限定された職務の明記 / 一部兼務の明記 / 複数領域を横断する職務の明記 |
| 顧客との接点 | 顧客や利用者とどの程度直接関わりたいですか？ | 直接の接点は少ない / ときどき関わる / 日常的に関わる | 直接接点のない職務の明記 / 定期的な接点の明記 / 日常的な顧客対応・共同作業の明記 |

### アンカーのレビュー例

以下は公開求人の記載を仮定した例であり、実在の企業を評価したものではない。各列には明示的な記載がある場合だけ対応するアンカーを使う。

| 軸 | 0の例 | 50の例 | 100の例 |
|---|---|---|---|
| 働く場所 | 「週5日オフィス勤務」 | 「週3日出社・週2日在宅」 | 「出社不要、完全在宅」 |
| 裁量 | 「定められた手順に沿って実施」 | 「担当範囲では手順を選択可能」 | 「業務方針から自ら決定」 |
| 協働 | 「一人で担当案件を完結」 | 「個人業務と共同業務を担当」 | 「チームで共同して成果物を作成」 |
| 成長の方向 | 「既存の専門分野を深める職務」 | 「専門業務と新領域の業務を兼務」 | 「未経験の領域を開拓する職務」 |
| 仕事の変化 | 「決まった業務を定期的に実施」 | 「定型業務と変化する案件の両方を担当」 | 「頻繁に変わる優先順位へ対応」 |
| 勤務時間の柔軟性 | 「勤務時間9:00〜18:00固定」 | 「始業時刻を一定範囲で選択可」 | 「コアタイムなしのフレックス」 |
| 役割の幅 | 「担当領域は一つの専門分野」 | 「専門業務に加えて別領域を一部兼務」 | 「企画・実装・運用を横断して担当」 |
| 顧客との接点 | 「顧客との直接接点なし」 | 「月次の顧客打ち合わせに参加」 | 「日常的に顧客と共同作業」 |

## 評価時の扱い

- 公開資料の基準は、企業全体と個別求人を区別して適用する。会社の一般的な制度を、個別求人の勤務条件や職務内容として推測しない。
- 「50」は両端の記載がないことを意味しない。中間的な条件が明示されている場合に使う。
- 根拠が見つからない場合は `unknown` を返し、数値を付けない。`unknown` を0や50に置き換えない。矛盾する記載は `conflicting`、古い資料は `stale` と区別する。
- Jevには軸ごとの狭い問いと公開資料を渡す。Jev Scoreをこの0〜100尺度や適合率へ直接変換しない。根拠として出典URL・箇所・取得日を保持する。
- 最低年収、勤務地、フルリモート必須などのHard Constraintは別の入力と判定にする。働く場所の希望値だけで「フルリモート必須」を表さない。

## 重要度と必須条件

- `preference` と `importance` は、同じ数値であっても別の意味を持つ。`importance=0` は未回答ではなく「この軸をマッチ判定に用いない」。希望値はプロフィール版に残す。
- 最低年収は日本円の額面年収で指定する。求人に同じ単位で金額または範囲が明示された場合、掲載範囲の下限が最低年収以上なら条件を満たす。上限が最低年収未満なら条件に合わない。範囲が基準をまたぐ場合は `unknown` とする。金額・通貨・期間が不足または異なる場合も、未承認の換算を行わず `unknown` とする。
- 勤務地は本人が許容する地域と、個別求人に明示された選択可能な勤務地を比較する。許容地域で勤務できることが明示されれば条件を満たす。必須勤務地がすべて許容外と明示されれば条件に合わない。勤務地や選択可否が不明なら `unknown` とする。
- フルリモート必須を指定した場合、個別求人に出社不要と明示されれば条件を満たす。定期的な出社が必須と明示されれば条件に合わない。記載がない、または会社全体の制度しか分からなければ `unknown` とする。必須指定がなければ、このHard Constraintによる除外は行わない。
- 必須条件が `unknown` の場合は、条件を満たしたとも違反したとも表示しない。公開情報に基づく確認結果として示す。

| 確認例 | 判定 |
|---|---|
| 最低年収500万円、求人の額面年収が550万〜700万円 | 満たす |
| 最低年収500万円、求人の額面年収が350万〜450万円 | 合わない |
| 最低年収500万円、求人の額面年収が450万〜600万円 | `unknown` |
| フルリモート必須、求人には会社全体のリモート制度のみ記載 | `unknown` |
| 勤務地の選択可否が記載されていない | `unknown` |

## 別途決める事項

MatchEngineの軸間の比較・重み付け、Jev出力から観測値への変換、APIでの `unknown` のJSON表現、地域名の入力単位と正規化は後続Issueで決める。これらの未確定事項を推測して実装しない。
