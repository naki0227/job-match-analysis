# Design Doc の形（新しいプロダクト・大きな機能）

リポジトリに Design Doc・ADR・Issue の決まった置き場があればそこに、無ければ `docs/design/YYYY-MM-DD-<短い名前>.md` に置く。**本人に判断してほしいことを先頭に書く。** 細部は下に。

```markdown
# 〈名前〉

## 決めてほしいこと
- 〈作るか／どれを作るか／足りない条件〉 — 推し: 〈案〉（理由1行）

## 1. 課題
〈だれ〉が〈どんな場面〉で〈何〉に困っている／〈何〉ができたらうれしい。
材料: 〈使ってみた結果・Issue・計測・声〉

## 2. 疑った前提
| 前提 | 疑った結果 | 証拠の強さ |
|---|---|---|
反証として探したもの: 〈…〉 → 〈見つかった／見つからなかった〉
捨てた課題: 〈課題〉 — 〈理由〉

## 3. 影響
- 誰に / どんな / どれくらい（前提つきの幅）
- 悪い影響と、その負担者
- 測り方: 〈指標〉 〈目標値〉 〈いつ測るか〉

## 4. 作るもの
- 洗い出した解き方と、外した理由
- 選んだもの: 〈…〉
- 最小の形: 〈…〉
- 作らないもの: 〈…〉

## 5. 制約・状況
費用 / 障害の許容 / 性能 / プライバシー / 期限と人 / 既存の状況（未確認は未確認と書く）

## 6. 作り方
技術と版（確かめた日付・出典）、設計の要点、制約ごとの満たし方、採らなかった案

## 7〜12. 確かめ方と出し方
形で確かめること / テストと E2E / 性能の目標と条件 / リリースの順序・段階・戻し方 / 運用で見るもの

## 見直す条件
〈何が変わったら、この判断をやり直すか〉
```
